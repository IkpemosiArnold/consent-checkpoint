Consent Checkpoint Sample data

An approval checkpoint before an agent shares an offer.

Seven offers an agent queued for a made-up coalition. Plain code checks consent, approval and retries against the records, and a retry whose consent has run out is blocked.

Before the agent can send one member's details to a partner, five things must hold. There is a consent row for that member and that recipient. The consent is still good at the moment of sending, and a retry is checked again at retry time, not at the first attempt. Every field in the message is one the consent allows. A named person approved this exact version, after its last edit. And it has not already been delivered. All times are UTC.

A consent row's expiry date is the last day it is good for, to 23:59 UTC. Consent for one recipient is never stretched to another. A retry reuses the first attempt's key, so the receiver can drop a duplicate; if the message changed since then, a person confirms before it goes under a new key. Anything the records do not show is held with what is missing, and nothing is guessed.
